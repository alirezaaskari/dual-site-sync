# Dual Site Sync

همگام‌سازی دستی محصولات ووکامرس بین دو فروشگاه، به‌همراه انتقال داده‌های افزونه‌ی
**Variation Swatches for WooCommerce** (نسخه رایگان و Pro).

بازنویسی کامل نسخه‌ی تک‌فایلی قبلی: کلیدهای API از کد حذف شده‌اند، احراز هویت با
امضای HMAC انجام می‌شود، و کد به کلاس‌های مستقل تقسیم شده تا داخل چایلد تم فلت‌سام
قرار بگیرد.

## نصب

روی **هر دو سایت** یکسان انجام دهید.

### ۱. چایلد تم

پوشه‌ی `flatsome-child/` را در `wp-content/themes/` بگذارید و فعالش کنید.
اگر از قبل چایلد تم دارید، فقط `inc/dual-site-sync/` را کپی کنید و این بلوک را به
انتهای `functions.php` خودتان اضافه کنید:

```php
$dss_bootstrap = get_stylesheet_directory() . '/inc/dual-site-sync/bootstrap.php';

if ( file_exists( $dss_bootstrap ) ) {
	require_once $dss_bootstrap;
}
```

از `require_once` بدون شرط استفاده نکنید: اگر مسیر اشتباه باشد یا فایل‌ها هنوز
آپلود نشده باشند، `require_once` خام کل سایت را با Fatal error پایین می‌آورد و
دسترسی به پیشخوان را هم از دست می‌دهید. با `file_exists` فقط ماژول لود نمی‌شود.

پس از آپلود، ساختار باید دقیقاً این باشد (لینوکس به حروف کوچک/بزرگ حساس است):

```
wp-content/themes/flatsome-child/
├── style.css
├── functions.php
└── inc/
    └── dual-site-sync/
        ├── bootstrap.php
        ├── assets/
        └── includes/
```

اگر بعد از extract یک لایه‌ی اضافه دیدید (مثلاً
`flatsome-child/flatsome-child/inc/…`)، محتویات پوشه‌ی داخلی را یک سطح بالا
بیاورید.

### ۲. تنظیمات wp-config.php

محتویات `docs/wp-config-snippet.php` را در `wp-config.php` هر دو سایت، بالای خط
`/* That's all, stop editing! */` قرار دهید.

کلید رمز مشترک را با این دستور بسازید و **در هر دو سایت عیناً یکسان** بگذارید:

```bash
openssl rand -hex 32
```

### ۳. بررسی

**تنظیمات ← همگام‌سازی دو سایته** را باز کنید و دکمه‌ی «آزمایش اتصال» را بزنید.
باید نام سایت مقابل و نسخه‌ی افزونه را نشان دهد.

### ۴. ابطال کلیدهای قدیمی

کلیدهای `ck_…` / `cs_…` نسخه‌ی قبلی دیگر استفاده نمی‌شوند. آن‌ها را از
**ووکامرس ← تنظیمات ← پیشرفته ← REST API** در هر دو سایت **حذف** کنید.

## دکمه‌ها

متاباکس «همگام‌سازی دو سایته» در ستون کناری صفحه‌ی ویرایش محصول ظاهر می‌شود و از
طریق **تنظیمات صفحه** (بالای صفحه) قابل مخفی کردن است.

| دکمه | چه چیزی می‌فرستد |
|---|---|
| **همگام‌سازی کامل** | نام، توضیحات، قیمت، دسته/برچسب، ویژگی‌ها، واریشن‌ها، تصاویر، تنظیمات سواچ |
| **همگام‌سازی بدون تصاویر** | همان موارد، ولی **هیچ تصویری** منتقل نمی‌شود: نه شاخص، نه گالری، نه تصویر واریشن، نه تصویر سواچ/تولتیپ |
| **به‌روزرسانی جزئی** | قیمت، توضیح کوتاه، دسته/برچسب، ویژگی‌ها، تصاویر، سواچ — نام و توضیحات کامل دست‌نخورده می‌ماند |
| **ایجاد محصول در سایت دیگر** | فقط وقتی محصول هنوز به سایت مقابل متصل نشده؛ پس از موفقیت خودکار مخفی می‌شود |

موجودی در هیچ‌کدام ارسال نمی‌شود مگر در تنظیمات فعالش کنید.

## تنظیمات

**تنظیمات ← همگام‌سازی دو سایته** (منوی «تنظیمات» وردپرس)

| گروه | گزینه | پیش‌فرض |
|---|---|---|
| محتوا | دسته‌بندی‌ها و برچسب‌ها منتقل شوند | روشن |
| | برندها منتقل شوند | روشن |
| | تصویر واریشن‌ها منتقل شود | روشن |
| | دسته‌بندی‌های نبود ساخته شوند | روشن |
| | وضعیت انتشار منتقل شود | **خاموش** |
| | واریشن‌های حذف‌شده در مقصد هم حذف شوند | روشن |
| سواچ | تنظیمات سواچ محصول منتقل شود | روشن |
| | رنگ/تصویر/تولتیپ ترم‌ها منتقل شود | روشن |
| موجودی | فیلدهای موجودی در همگام‌سازی دستی ارسال شوند | **خاموش** |
| | انبار مشترک (پوش خودکار موجودی) | **خاموش** |
| خودکارسازی | همگام‌سازی خودکار پس از ذخیره | **خاموش** |
| SKU | ساخت خودکار SKU واریشن | **خاموش** |
| | SKU دستی واریشن بازنویسی نشود | روشن |
| فرانت‌اند | جست‌وجوی محصول با SKU | روشن |

«انبار مشترک» را فقط وقتی روشن کنید که واقعاً یک انبار فیزیکی مشترک دارید، و باید
در **هر دو** سایت روشن باشد.

## امنیت

| مورد | نسخه‌ی قبلی | نسخه‌ی فعلی |
|---|---|---|
| کلیدها | `ck_…`/`cs_…` داخل سورس | `DSS_SHARED_SECRET` در `wp-config.php` |
| انتقال | secret در query string (لاگ می‌شد) | امضای HMAC-SHA256 در هدر؛ کلید هرگز منتقل نمی‌شود |
| مقایسه | `===` | `hash_equals` |
| سایت فرستنده | کلید خودِ سایت هم پذیرفته می‌شد | فقط کلید سایت مقابل |
| بازپخش درخواست | محافظتی نداشت | مهر زمانی ±۵ دقیقه + nonce یک‌بارمصرف |
| یکتایی SKU | سراسری خاموش شده بود | فقط در طول یک عملیات همگام‌سازی |
| جست‌وجوی SKU | `OR` از پرانتز بیرون می‌زد و پیش‌نویس/زباله را عمومی می‌کرد | تزریق داخل پرانتز، فقط `publish` |
| مسیر قدیمی REST | فعال | پاسخ `410 Gone` |

## داده‌های افزونه‌ی سواچ

انتقال خام متاهای این افزونه بین دو سایت **غلط** است، چون `term_id` و
`attachment_id` در دو سایت یکی نیستند. کلاس `DSS_Swatches` این نگاشت‌ها را انجام
می‌دهد:

| داده | محل | نگاشت |
|---|---|---|
| تنظیمات سواچ محصول | postmeta `_woo_variation_swatches_product_settings` | کلید ترم‌ها `term_id ⇄ slug` |
| تصویر و تولتیپ در تنظیمات محصول | همان متا، کلیدهای `image_id` / `tooltip_image_id` | `attachment_id ⇄ URL` |
| رنگ ترم | termmeta `product_attribute_color`, `secondary_color`, `is_dual_color` | مستقیم |
| تصویر ترم | termmeta `product_attribute_image`, `image_size` | `attachment_id ⇄ URL` |
| تولتیپ ترم | termmeta `show_tooltip`, `tooltip_text`, `tooltip_image_id` | متن مستقیم / تصویر با URL |
| گروه ترم | termmeta `group_name` → option `woo_variation_swatches_groups` | گروه ارجاع‌شده در مقصد ساخته می‌شود |

پس از نوشتن، اکشن `woo_variation_swatches_product_settings_update` صدا زده می‌شود
تا کش داخلی خود افزونه پاک شود.

## تصاویر اضافی واریشن

ووکامرس برای هر واریشن فقط **یک** تصویر دارد. فیلد «Additional images» زیر هر
واریشن از افزونه‌ی جانبی می‌آید و فهرست شناسه‌ی پیوست‌ها را در متای واریشن نگه
می‌دارد. چون شناسه‌ی پیوست در دو سایت یکی نیست، مثل بقیه‌ی تصاویر به URL ترجمه و
در مقصد به شناسه‌ی محلی برگردانده می‌شود.

تشخیص افزونه خودکار است:

| کلید متا | افزونه | شکل ذخیره |
|---|---|---|
| `_wc_additional_variation_images` | WooCommerce Additional Variation Images | رشته‌ی جداشده با کاما |
| `additional_variation_images` | نسخه‌های قدیمی همان افزونه | رشته‌ی جداشده با کاما |
| `rtwpvg_images` | RadiusTheme Variation Images Gallery | آرایه |
| `woo_variation_gallery_images` | Variation Images Gallery (GetWooPlugins) | آرایه |

قاعده‌ی انتقال:

- کلیدی که روی واریشن مبدأ **ردیف متا ندارد** اصلاً منتقل نمی‌شود و در مقصد
  دست‌نخورده می‌ماند.
- کلیدی که ردیف دارد ولی **خالی است**، در مقصد هم **پاک می‌شود** تا دو سایت
  دقیقاً یکی باشند. همین رفتار، تصاویر اضافیِ اشتباهاً پرشده را در همگام‌سازی
  بعدی تمیز می‌کند.
- فقط کلیدهای فهرست بالا نوشته می‌شوند؛ کلید ناشناخته در بسته نادیده گرفته
  می‌شود. برای افزودن کلید دیگر از فیلتر `dss_variation_gallery_meta_keys`
  استفاده کنید.

در **تنظیمات ← همگام‌سازی دو سایته** ردیف «تصاویر اضافی واریشن» نشان می‌دهد این
سایت کدام کلید را واقعاً استفاده می‌کند.

## برندها

تاکسونومی برند بسته به افزونه نام متفاوتی دارد. DSS این‌ها را تشخیص می‌دهد و فقط
آن‌هایی را منتقل می‌کند که واقعاً روی سایت ثبت شده‌اند:

| تاکسونومی | منبع |
|---|---|
| `product_brand` | ووکامرس ۹.۴+ (داخلی) و افزونه‌ی WooCommerce Brands |
| `pwb-brand` | Perfect WooCommerce Brands |
| `yith_product_brand` | YITH WooCommerce Brands |
| `berocket_brand` | BeRocket Brands |

برند فقط زمانی منتقل می‌شود که **همان** تاکسونومی روی سایت مقابل هم ثبت شده باشد؛
یعنی افزونه‌ی برند باید در هر دو سایت یکی باشد. برندهای نبود در مقصد ساخته
می‌شوند. برای افزودن تاکسونومی دیگر از فیلتر `dss_brand_taxonomies` استفاده کنید.

## نگاشت تصاویر

هر پیوستی که از سایت مقابل دانلود می‌شود دو متا می‌گیرد:

- `_dss_source_url` — آدرس اصلی در سایت مبدأ
- `_dss_source_hash` — `md5` محتوای فایل

ترتیب جست‌وجو: متای آدرس ← پیوست محلی (اگر آدرس متعلق به همین سایت باشد) ← هش
محتوا. جایگزین روش قبلی که با `LIKE '%نام-فایل%'` کار می‌کرد و تصاویری با نام
مشترک (`1.jpg`) را به محصولات اشتباه وصل می‌کرد.

## پیوند بین دو سایت

| متا | معنی |
|---|---|
| `_dss_remote_id` | شناسه‌ی همتا در سایت مقابل |
| `_dss_remote_site` | کلید سایت مقابل (`site_a` / `site_b`) |
| `_dss_created_by_site` | سایتی که محصول را اولین بار ساخته |
| `_dss_last_sync` | زمان آخرین همگام‌سازی |

پیوند روی **هر دو** سایت نوشته می‌شود؛ به همین دلیل دکمه‌ی «ایجاد» پس از موفقیت
ناپدید می‌شود و امکان ساخت محصول تکراری از بین می‌رود. متاهای قدیمی
`_source_id` / `_source_site` برای سازگاری همچنان خوانده و نوشته می‌شوند.

## مولد SKU اختصاصی

اگر مولد SKU خودتان را دارید (`lotus_auto_generate_sku`)، نسخه‌ی به‌روزشده‌ی همان فایل در
`docs/customskufeatures.php` است. جزئیات در همان فایل توضیح داده شده.

خلاصه: DSS هنگام ساخت محصول در مقصد، SKU را **پیش از نخستین ذخیره** می‌نویسد، پس
مولدهای مبتنی بر `save_post_product` خودشان کنار می‌کشند. برای اطمینان بیشتر،
محافظ `DSS_Context::is_syncing()` هم به مولد اضافه شده است.
